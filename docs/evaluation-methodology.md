# 评估方法学：检索与忠实度双维度

## 一、为什么两个维度缺一不可

检索指标回答的是「该找到的段落找到了吗」，忠实度回答的是「答案是否只说了这些段落里的话」。
只测检索会漏掉最危险的一类问题：段落找对了，模型却自己加了一句「因此生产环境建议关闭该
功能」——引用看起来齐全，结论是编的。只测忠实度也不行：模型可以老老实实地基于错误的段落
给出一个「忠实的错误答案」。

所以最终评估集是二维的：每个问题同时产出检索排名与忠实度得分。

## 二、检索维度：Recall@K 与 MRR

Recall@K 的判定是二值的：前 K 条里至少出现一条相关片段就算命中，因此它对「相关片段排在
第 3 还是第 5」不敏感。K 取 3 和 5 两档，因为线上只把前 3 条塞进提示词。

MRR 取首个相关片段排名的倒数再平均：排第 1 得 1.0，排第 2 得 0.5，排第 3 得 0.33。它
衡量正确的东西排得多靠前，对重排这类微调远比 Recall 敏感。

这就是为什么必须跑两臂：向量粗召回是一臂，含重排的全链路是另一臂。语料小的时候两臂的
Recall 都容易顶到 1.00，唯一能动的就是 MRR。

## 三、双条件判分

一个片段算相关，必须同时满足两条：来源文件名对得上，且正文包含这道题指定的锚点原文。

只对文件名会让同一篇文档里的任意片段都算命中，指标虚高到没有意义。只看锚点又会让别的
文档碰巧复述同一句话时判错。两条同时成立，才叫找到了该找的那一段。

锚点必须是一段能在原文里逐字找到的短语，并且落在单个切片内。跨切片的锚点永远判不中，这种
题会污染整个指标，写题时就要避开。

## 四、忠实度维度：claim 级判定

忠实度不是让模型给答案打一个可信度分——那种分数没有定义，也不可复现。做法是把答案拆成
原子断言，逐条判断这条断言能否由给定的引用片段直接推出。

每条断言标注是否被支持，同时给出支撑它的引用编号。分数等于被支持的断言数除以断言总数，
逐题算完再对题目取平均。同时报告微平均（把所有断言汇总后算），两者差距大说明有个别题目
断言特别多，拉偏了均值。

引用片段是判定时唯一允许的证据来源，不把整篇文档或检索全量喂给裁判。理由是：模型若看到
引用之外的原文，会把「文档里确实这么写」当成「答案被支持」，而真正要测的是答案是否被它
声称的引用支持。

答案里没有任何可判定的断言（例如直接说没找到）时，记为弃答而不是满分：既不算幻觉，也
不能算作了答对。

## 五、LLM 裁判的偏差与缓解

用大模型当裁判有三个已知偏差，这里都做了针对性处理。

第一是宽松倾向：模型倾向于判基本正确。缓解办法是要求逐条断言判定并输出结构化结果，而不
是让它给一个整体印象分；整体分几乎总是偏高。

第二是自我偏好：同族模型倾向于认可同族模型的输出。这里生成与判定用同一个模型，属于明确
接受的局限——它会让忠实度略微偏高，读数字时要打点折扣。彻底解决需要引入异族裁判模型或
人工抽检。

第三是格式鲁棒性：裁判可能返回带围栏的 JSON、可能多一句解释、可能字段缺失。解析器必须
容错，解析失败就记为判定失败并如实计入报告，不能静默当成通过。

## 六、样本量与基线

样本量决定数字的意义。随机基线约等于 K 除以切片总数：9 个切片、K 取 3 时随机基线高达
0.56，Recall@3 等于 1.00 几乎证明不了任何事。语料扩到 50 个切片以上，随机基线才降到
0.1 以下，指标才开始有区分度。

另一个必须承认的偏差是域内自建：题目由读过语料的人出，用词与原文接近，真实用户的问法会
更口语、更跳跃。所以这里的绝对值只能用于回归对比（改动前后是否变差），不能对外宣称
「本系统检索准确率 95%」。

判断标准因此写成门槛而不是目标：Recall@3 低于阈值、忠实度低于阈值，就以非零码退出，接进
CI 当回归门禁。
