# API 契约与安全边界

## 一、认证

注册即签发访问令牌，不需要二次登录。密码用 bcrypt 哈希存储，不存明文也不存可逆摘要。

为什么不用 passlib：它 1.7.4 版本会读取 bcrypt 的私有属性，在 bcrypt 4.1 以上直接崩掉，
直接调 bcrypt 三行代码就能解决，省掉一个长期踩坑源。

JWT 用 HS256 签名，默认有效期 1440 分钟。所有业务接口都通过 Bearer 令牌取当前用户，
令牌里只放用户 id，不放邮箱与权限——用户信息变更时不必等令牌过期。

## 二、错误契约

错误响应统一结构：error 对象包含 code、message、details 三个字段。code 供客户端分支，
message 面向用户，details 只在需要排障时出现。

几个关键映射：参数校验失败 422；认证失败 401；邮箱重复 409；超出限流 429；外部 I/O 超时
或重试耗尽 504；Agent 输出未通过 Pydantic 校验 502。

最后一条是刻意选的：502 表示上游给了不合规的东西，而不是 500 表示服务自己崩了。把输出
校验失败和内部异常分开，排障时才不会把模型抽风和代码 bug 混为一谈。

## 三、对话接口

对话端点一个地址两种形态，由请求体的 stream 字段决定。stream 为 true 时返回
text/event-stream，为 false 时返回完整 JSON，两者字段完全一致，前端可以先用非流式调试，
再切流式。

SSE 有六个事件：start 只带会话 id 与模型名；route 带路由结果、判断来源与理由；citations
带本轮引用列表；token 每个增量一帧，载荷是一个文本字段；done 带完整响应体；error 带错误
码与提示。收到 error 后客户端应丢弃已拼接内容。

响应头里必须带关闭缓冲的标记。nginx 默认会缓冲上游响应，不关掉的话 SSE 会被攒成一包
一次性下发，看起来是流式失效，实际是反向代理在缓冲。

## 四、数据模型

四张表承担全部状态：用户表存账号与密码哈希；文档表存正文、来源与切片数；消息表存每一轮
问答，助手消息额外带引用列表的 JSON；用量表存每次调用的 token 数、路由、延迟与估算成本。

用量表是成本台账的唯一来源，用量汇总接口直接对它做聚合，不需要额外埋点。文档表的切片数
是索引自检的依据：它与向量库条数比对，不一致就触发重建。

## 五、安全边界

Key 只存在于服务端进程的内存与环境变量里，永不下发到客户端，也不写进日志。日志里只记
有没有配 Key，不记 Key 本身。

SQL 只读校验在模式校验层完成，执行层再用行数上限兜底，两道防线都不能省：只读校验防写入，
行数上限防拖库。

环境变量文件永远不进版本库，示例文件只放占位符。曾经把带真实 Key 的配置误提交过一次，
之后用全历史扫描确认无残留，并撤销了旧令牌——这类事故只能靠流程防，不能靠记性。
